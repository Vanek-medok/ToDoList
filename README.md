# ToDoList API

REST API для управления списком задач, написанный на Go с использованием PostgreSQL.

Проект создан для практики backend-разработки: построения REST API, разделения приложения на слои, работы с базой данных, обработки ошибок, логирования и контейнеризации с помощью Docker.

## Возможности

- Создание задачи.
- Получение списка задач.
- Удаление задачи.
- Изменение статуса задачи.
- Получение справочной информации об API.
- Хранение задач в PostgreSQL.
- Обработка ошибок и логирование событий приложения.
- Корректное завершение HTTP-сервера при получении `SIGINT` или `SIGTERM`.
- Запуск приложения в Docker-контейнере.

## Технологии

- **Go** — основной язык разработки.
- **net/http** — HTTP-сервер и обработка запросов.
- **PostgreSQL** — хранение данных.
- **pgx/v5** — взаимодействие с PostgreSQL.
- **Docker** — контейнеризация приложения.
- **Docker Compose** — настройка и запуск контейнера.
- **SQL migrations** — управление изменениями схемы базы данных.
- **slog** — структурированное логирование.

## Архитектура

Приложение организовано с разделением ответственности между основными слоями:

- **Handlers** — обработка HTTP-запросов, чтение входных данных и формирование ответов.
- **Services** — бизнес-логика приложения.
- **Repositories** — взаимодействие с PostgreSQL.
- **Database** — настройка подключения к базе данных.
- **Config** — загрузка конфигурации приложения.
- **Server** — регистрация маршрутов и настройка HTTP-сервера.

Такое разделение упрощает сопровождение приложения и позволяет развивать отдельные части системы независимо друг от друга.

## API

Базовый адрес при локальном запуске: `http://localhost:8080`.

| Метод | Эндпоинт | Назначение |
|---|---|---|
| `GET` | `/tasks` | Получить список задач |
| `POST` | `/tasks` | Создать задачу |
| `GET` | `/tasks/help` | Получить справочную информацию |
| `PATCH` | `/tasks/{id}` | Изменить статус задачи |
| `DELETE` | `/tasks/{id}` | Удалить задачу |

### Примеры запросов

Базовый адрес API при локальном запуске: `http://localhost:8080`.

#### Получение списка задач

**Запрос:** `GET /tasks`

```bash
curl -i http://localhost:8080/tasks
```

#### Создание задачи

**Запрос:** `POST /tasks`

Для создания задачи необходимо передать её название (`title`) и описание (`description`). Идентификатор, время создания и статус задачи формируются приложением.

```bash
curl -X POST http://localhost:8080/tasks \
  -H "Content-Type: application/json" \
  -d '{
    "title": "пятая задача",
    "description": "выгулять собаку"
  }'
```

Пример тела запроса:

```json
{
  "title": "пятая задача",
  "description": "выгулять собаку"
}
```

Пример возможного ответа с созданной задачей:

```json
{
  "id": 5,
  "title": "пятая задача",
  "description": "выгулять собаку",
  "created_at": "2026-10-19T12:00:00Z",
  "completed": false,
  "completed_at": null
}
```

*Ответ приведён для иллюстрации структуры данных. Фактический ответ зависит от реализации обработчика.*

#### Изменение статуса задачи

**Запрос:** `PATCH /tasks/{id}`

```bash
curl -i -X PATCH http://localhost:8080/tasks/5
```

#### Удаление задачи

**Запрос:** `DELETE /tasks/{id}`

```bash
curl -i -X DELETE http://localhost:8080/tasks/5
```

#### Получение справочной информации

**Запрос:** `GET /tasks/help`

```bash
curl -i http://localhost:8080/tasks/help
```

Формат ответов и коды HTTP-статусов определяются реализацией соответствующих обработчиков.

## Конфигурация

Приложение использует переменные окружения:

| Переменная | Назначение |
|---|---|
| `DATABASE_URL` | Строка подключения к PostgreSQL |
| `PORT` | Порт HTTP-сервера |

Создайте файл `.env` в корне проекта:

```dotenv
DATABASE_URL=postgres://postgres:YOUR_PASSWORD@localhost:5432/todolist?sslmode=disable
PORT=8080
```

Замените `YOUR_PASSWORD` на пароль пользователя PostgreSQL.

**Не добавляйте `.env` с реальными секретами в Git.** Для публикации проекта можно добавить `.env.example` с демонстрационными значениями без настоящих паролей.

При запуске приложения в Docker, если PostgreSQL работает на хостовой машине Windows, в `DATABASE_URL` вместо `localhost` необходимо использовать `host.docker.internal`.

## Запуск через Docker Compose

Предварительно установите Docker и Docker Compose. Убедитесь, что PostgreSQL запущен, база данных `todolist` создана, а сервер БД принимает подключения из Docker-контейнера.

Соберите образ и запустите приложение:

```bash
docker compose up --build -d
```

Проверьте состояние контейнера:

```bash
docker compose ps
```

Посмотрите логи приложения:

```bash
docker compose logs -f application
```

После запуска API доступен по адресу:

`http://localhost:8080`

Остановите контейнер:

```bash
docker compose down
```

Для перезапуска приложения:

```bash
docker compose restart application
```

Логи приложения сохраняются в каталоге `logs/`, подключённом к контейнеру через Docker volume.

## Завершение работы

Приложение обрабатывает сигналы `SIGINT` и `SIGTERM`. При завершении работы HTTP-сервер пытается корректно обработать активные запросы в пределах заданного тайм-аута, после чего закрывается соединение с базой данных.

Это позволяет избежать резкого завершения приложения при штатной остановке контейнера.
